# 皇室战争 全部徽章图鉴

一个**离线可用的单文件网页图鉴**，收录《皇室战争》游戏内可查看的**玩家徽章**（Badge）。
所有图像均由游戏内精灵文件重建渲染 —— 双击 `index.html` 即可浏览。

## 特性

| 数量 | 说明 |
| --- | --- |
| **200** | 徽章条目 |
| **1597** | 等级图，同级可选、逐级变样式（图示最高等级） |
| **6** | 徽章类型（普通 / 稀有 / 史诗 / 传说 / 冠军 / 归档） |

其中：

- **78** 个带独立徽章图的系列徽章（经典挑战 / 终极挑战 / CRL 等），共 **377** 张等级图；
- **122** 个**卡牌大师徽章**（Mastery），共 **1220** 张等级图（每卡 10 级）。
  这批徽章游戏里**没有现成精灵**，由「通用精通框 + 卡牌图标」现场合成，见下文。

> 另有 4 个徽章（`CrazyArenaCompletion`、`CrazyArenaRank`、`TripleDraftLeagueCompletion`、
> `TripleDraftLeagueRank`）数据表声明了 10 级，但当前游戏素材只到第 1~2 级，
> 因此仅收录素材已有的等级，并在卡面与灯箱标注「部分收录」。
>
> 1 个卡牌大师徽章（**亡灵巨人 / `MasteryMinionGiant`**）在图标目录里没有对应图标，未收录。

交互功能：

- **搜索** —— 名称 / 数据名 / 导出名 / TID / 进度要求模糊匹配
- **筛选** —— 分类下拉（全部 / 独立徽章 78 / 卡牌大师 122）、徽章类型下拉、`多等级`（仅看可升级，等级数 ≥ 2）
- **排序** —— 排序值（SortOrder）/ 名称 A→Z / 按类型分组 / 按等级数
- **详情灯箱** —— 大图 + 等级缩略图条（点选切换）+ 等级一览与获得条件，`←` `→` 翻页、`↑` `↓` 换等级、`Esc` 关闭
- **中 / EN 切换** —— 名称与说明取自游戏文案表（`texts.csv` 的 CN / EN 列）
- **卡牌大师标记** —— 合成徽章在卡面与灯箱带「卡牌大师」标签，并显示所用角色图文件名

## 独立徽章渲染注意点

- 78 个系列徽章由 `build/build_assets.py` 从 `badges.csv` + `csv_client/texts.csv` + `_sc1/ui_badges_sc1.sc` 生成；`index.html` 内联的 `const META` 由 `build_assets.py` 自动同步（只替换独立徽章，保留卡牌大师数据）。
- ⚠️ **`apply_masks=True` 必须开（2026-09-22）**：徽章是「Mask 形状 + Masked 内容 + Unmasked 高光」结构，不开的话**遮罩形状会被当普通图形画出来** —— 表现为**白六边形底板 / 白色内块**，这就是用户反馈的「独立徽章有一圈白边」。
- ⚠️ **完成徽章 / 排名徽章各用各的素材（2026-09-22）**：联赛与锦标赛各有「完成（`*Completion`）」和「排名（`*Rank`）」两个徽章，数据表里它们指向**不同系列**：
  - 完成 → `*_silver_badge*` / `*_silver*`（青银色，如 `princessgambit_silver_badge_lvl1`）
  - 排名 → `*_ranked_badge*` / `*_gold_badge*` / `*_retro_badge*`（金色，如 `princessgambit_ranked_badge_lvl1`）

  两组**不得互相替换**。曾经为修「白边」加过「把完成徽章全等级映射到金色系列」的 `LV_REMAP`，结果是完成徽章和排名徽章渲染成了**同一张图**（9 对：2v2 / ChaosDraft / ChaosMegaDraft / Anarchy / CrazyArena / Royal / ClassicRoyale / SuddenDeath / TripleDraft），已按用户要求移除。**白边与用哪个系列无关** —— 只要 `apply_masks=True` 就不白，`_silver` 系列本身渲染出来是青紫色。
- 只做**同一徽章内**的重复导出名去重（CSV 里 `AnarchyLeagueCompletion` 的 10 行等级有 9 行都指向 `..._lvl2`，属数据错误）。

## 快速开始

无需安装、无需联网，直接双击打开 `index.html`。

## 目录结构

```
.
├── index.html              # 自包含单文件页面（数据内联）
└── assets/
    ├── badges/             # 333 张 PNG（独立徽章图，170px 高）
    └── mastery/            # 1220 张 PNG（卡牌大师合成图，170px 高）
```

原始数据表 `badges.csv` 与构建脚本、转存的 `.sc/.sctx` 均不入库（见 `.gitignore`），
重建时从游戏素材转储与卡牌图标目录重新读取即可。

## 重建

```bash
cd build
python fetch_assets.py     # 从官方 CDN 取 sc/ui_badges.sc → ScDowngrade 转 SC1
python build_assets.py     # 解析 badges.csv + texts.csv，渲染 PNG，产出 badges.json
python build_mastery.py    # 合成 122 个卡牌大师徽章，产出 assets/mastery/*.png + mastery.json
python build_page.py       # 合并两份数据，注入 template.html，产出 ../index.html
python verify_page.py      # 无头 Chrome 验证（卡片数 / 图加载 / 筛选 / 灯箱 / 中英切换 / 合成徽章）
```

`build_mastery.py` 支持 `--only key1,key2` 只渲染指定卡牌、`--force` 忽略已有图片全部重渲染、
`--fy 0.4` 指定纵向取景锚点（默认 **0.4**，配 `ZOOM=1.6`，见下文「取景」）；
`--zoom 1.6` 指定取景放大倍率（默认 **1.6**）。
⚠️ `--only` 会把 `mastery.json` **只写成那几条**，改完要补一次不带 `--force` 的全量跑恢复成 122 条。
⚠️ 渲染要挂后台跑（前台会被 SIGTERM）；全套 1220 张约 8~9 分钟（8 进程）。

`probe_mask_true.py` 量精通框的遮罩窗口（**纯品红注入法**，换精灵版本后重跑一次即可，见下文）；
`probe_window.py`（差分法）已废弃，仅留档。
自检 / 诊断工具：

| 脚本 | 用途 |
|---|---|
| `probe_mask_true.py` | **量遮罩窗口真值**（纯品红注入 + 坐标映射校准，输出槽位坐标 bbox/质心） |
| `hue_view.py <图名>` | **色相分类 ASCII**，不用看图就能读出框体内缘在第几行（首选） |
| `edge_sweep.py` | 逐边扫「内缩 k 后外圈 σ」，平段=框体、骤升=内缘；孤图手工定几何用 |
| `avg_groups.py` | 同尺寸组**平均图**（角色画抵消、框体留下）+ 每边色带平台厚度 |
| `anchor_grid.py` | **纵向锚点对照图**（源图可见区标注 + fy 0/.15/.30/.50 的实渲染） |
| `preview_fy.py` | 取景变体对照图，**不写** `assets/mastery` —— 试锚点先走它；变体写 `label:fy[:aspect[:top[:win]]]`，`win=legacy` 取旧窗口表 |
| `before_after.py` | 从 git HEAD 取旧图与当前图做**前后对照拼图** |
| `check_border.py` | 裁框自检（裁后外圈 σ + 裁切比例 + 所用几何） |
| `ring_profile.py <图名>` | 单图诊断，打印距边界每一圈的颜色标准差 |
| `diag_crop.py <卡名> [--lvls 1,5,10] [--fy X] [--win legacy\|x,y,w,h]` | 反解「渲染结果显示的是原图哪一块」+ **卡图中心相对盾形中心的偏移（槽位 px）** |
| `contact_sheet.py` | 「源卡 + 裁切/可见区框 \| 渲染结果」对照图，便于肉眼复核 |

`build/` 内含转存的 `.sc/.sctx`（约 7 MB）与渲染脚本，**不随页面发布**。

## 数据说明

### 独立徽章图

- 来自 `sc/ui_badges.sc`（SC2 原件从官方 CDN 取，`ScDowngrade` 转 SC1 后渲染）。
  注意部分转储里的该文件是 0 字节占位，正文在 `.sctx` 中，故 `.sc` 必须走 CDN；
  外部纹理 `.sctx` 必须与 `.sc` **同一版本**，否则纹理图集不匹配会渲染出碎片错图。
- 文案来自 `csv_client/texts.csv` 的 `EN` 与 `CN` 列，TID 一一对应。
- **模板行不是徽章**：`badges.csv` 里 `Name` 以 `Template` 开头的行（如 `TemplateMastery10`）
  只是给 `LevelsTemplate` 引用的通用框，收进来会变成「通用框 + 占位灰板」的假徽章，已剔除。
- **数据表比素材新**：`badges.csv` 里少数徽章声明了素材中不存在的等级导出
  （见上文 4 个「部分收录」徽章）。这类缺图不静默丢弃——`build_assets.py`
  只保留能渲染的等级并在数据里写入 `missTxt`，页面据此提示；只有整只都缺图才会剔除。

### 卡牌大师徽章（合成）

这批徽章（`LevelsTemplate=TemplateMastery10`）在精灵里只有 10 个**通用框**
（`mastery_badge_lvl1..10`），运行时才把对应卡牌的图填进框里。重建做法：

1. **定位填充槽**：`mastery_badge_lvlN` 的元素顺序是
   `[底层框] → [Mask: Shape 0] → [Masked: badge_art(资源 699, 119×151)] → [Unmasked: 高光/数字]`。
   所以要替换的就是资源 699，替换后遮罩照常生效。
   ⚠️ 渲染时必须开 `apply_masks=True`，否则 `Shape 0` 会被当成实心 `#CCFF00` 色块画出来。
2. **量出可视窗口**：`probe_mask_true.py` 用**纯品红注入法**——注入一张纯品红
   `(255,0,255)` 的 119×151 贴图（框体素材里没有这个颜色）渲染，结果里的品红像素
   就是遮罩真正露出的区域；再用外层返回的 `(canvas, ox, oy)` 反解贴图坐标：
   **`u = canvas_x + ox - ART_OX`**（`ART_OX/ART_OY` 是贴图原点在父空间的偏移）。
   实测三个抽样等级（1/5/10）包围盒几乎一致：**x∈[25,96]、y∈[33.5,115.5]**，
   **bbox 中心 (60.5, 74.5) ≈ 槽位中心 (59.5, 75.5) ⇒ 遮罩本身就是居中对称的盾形**
   （顶部宽、底部收尖）。`mastery_art.WIN_BY_LEVEL` 统一配 `(24,33,73,83)`
   （真值四周外扩 1px 防缝隙），由导出名里的 `lvlN` 自动选取。
   > ⚠️ **历史假象一（第二次返工）**：更早的探针用「alpha>200 且 **B<40**」判注入像素，
   > 但**框体自身的深色区域也满足 B<40** ⇒ 包围盒被框体拉偏。框体 lvl5 起长出侧翼、
   > 深色区一直延伸到 x≈117，于是量出「窗口随等级从 93 宽长到 117 宽」的**假表**。
   > 旧表保留在 `mastery_art.WIN_LEGACY_BY_LEVEL`，仅供 A/B 对照：
   > `preview_fy.py --var "旧窗口:0.1::0:legacy" --var "新窗口:0.1"`。
   >
   > ⚠️ **历史假象二（第六次返工，用户反馈「新版全部都偏移了」）**：
   > 中间版本的**差分法**（`probe_window.py`：坐标编码图 vs 纯黑图、差分∩B>200 反解 R/G）
   > 量出 `(14,19,77,87)`、中心 (52,62) —— 相比真值**整体偏左 8.5px、偏上 12.5px 且偏大**
   > （反解映射存在系统误差，具体环节未深究；「逐行中心从 x=38 漂到 x=71」也是它的伪影，
   > 纯白注入目视即可证伪）。用它做 cover 定位基准 ⇒ 卡图相对遮罩整体偏右下，
   > **1220 张成品全部偏移**；而旧线上版恰因「假窗口表 + 左右不对称边框几何」两个 bug
   > 抵消才显得居中。**教训：窗口量测必须用品红注入法 + 显式坐标映射校准**，
   > 任何「差分/反解」类测量都要先用已知注入图案核对坐标系再采信。
3. **取景**：卡图用 **`D:\CR\Usage\2026\icon\`** 里的卡面图标（带稀有度边框），
   先 `trim_alpha` 去掉透明边，**再按图逐边裁掉那圈稀有度边框**，最后按窗口做
   **cover** 缩放（`scale = max(宽比, 高比)`）+ **顶部对齐的纵向锚点**，保证两轴都 ≥ 窗口、**永不漏底**。
   > **`ZOOM=1.6` + `FY=0.4`（2026-09-21/22 用户两轮定案）**：真窗口 (24,33,73,83) 是遮罩
   > 可见区的精确尺寸，直接 cover 角色比线上旧版小 ~35%（旧版假窗口 93~117 宽 = 过度放大后
   > 靠遮罩裁边 ⇒「更大更满」的观感）。`zoom=1.6` 让大小回到旧版观感且居中正确、头部完整
   > （`zoom_compare.py` 出「HEAD 旧版 | z=1.0~1.9」对照选定）。
   > ⚠️ **zoom 与 fy 是一对**：`fy` 是「溢出量里留给顶部的比例」，zoom 变大 ⇒ 纵向溢出变大
   > ⇒ **同 fy 显示的源图区间整体下移 ⇒ 角色在窗口里偏下**——1.6 × fy 0.1 就是这样被
   > 用户打回「整体偏下」的；改用 `zoom_compare.py --zoom 1.6 --fys 0.1~0.7` 扫锚点，
   > 定 **fy=0.4**（脸落盾形中上、各等级头顶留白舒适；0.7 会头顶贴边）。
   > ⚠️ 旧数值只对 zoom=1.0 成立（仅留档）：zoom=1.0 时窗口相对裁后卡图是「宽」的，
   > 纵向溢出 28%（lvl10：139.5 → 100），fy=0.5 上下各切 14% ⇒ 正好切掉头顶；
   > 当时的 `fy=0.1`（顶部只切 2.2/7.0/7.9px）在 zoom=1.6 下不再适用。
   > 改锚点/zoom 一律先出 `zoom_compare.py` 对照确认，再全量重渲染。
   >
   > ⚠️ **为什么「不同等级头像位置/大小不一样」**（用户实测：电法 lvl1 vs lvl10）：
   > 真因是**窗口表本身量错了**（见上文第 2 步的历史假象一）。
   > 旧表下 cover 缩放被错误的窗口宽度绑定 —— `0.476`(lvl1) → `0.766`(lvl10)，
   > **高等级的头比 lvl1 大 60%**，纵向可见区间从卡图的 65% 缩到 51%，
   > 横向还从 **−5.4px 摆到 +11.1px**（lvl1 偏左、lvl10 偏右）。
   > 换成实测盾形窗口后（各等级一致 73×83）：缩放跨等级不变、横向居中 ±1px。
   > 试过但**已弃用**的另一条路：`VIEW_ASPECT`（把卡图预裁成固定宽高比，`crop_aspect()`）
   > —— 它把缩放强行改成「高度绑定」，表面上也跨等级一致，但会白裁掉卡图上下两端，
   > 且**掩盖了窗口量错这个真因**，用户验收不通过。
   > ⚠️ **定位必须是「减」溢出量**：窗口在「图自身坐标系」里的可见区间是
   > `[-(w-ww)·f, ww-(w-ww)·f]`，要居中就得是 `[(w-ww)/2, …]`，即 `left = x0-(w-ww)·fx`。
   > 曾经写成 `+`，`fx=0.5` 反而把图往右下推了一个溢出量 ——
   > 表现是**徽章里只显示卡图的左上半（人物头部）**，等级越高偏得越明显。
   > 素材库 `image/chr*/` 里的高清图是「角色 + 场景」的横构图大画布（角色常只占一角），
   > 塞进盾形窗口既不居中也会被裁没 —— 已改为只作兜底（`prep="scene"`）。
   >
   > **框体几何按「画布尺寸」定，不按单张图定**（`mastery_art.build_border_map()`）：
   > 图标要先 `trim_alpha`，同一尺寸的图标框体完全一致 —— 实测 280×340 组 63 张的
   > p10/p25/中位数都是 `(31, 30~33, 24, 22~23)`。所以对**全组**取 p25 当几何，
   > 一次绕开 `bandit`/`Evolved-Princess` 这类被角色画干扰、单图检测失准的样本。
   > `crop_border(geom=(T,B,L,R))` 按该几何**逐边**裁。
   > ⚠️ **不能四边统一取 min**：竖版卡的上下框（~31px）比左右（~23px）厚，
   > 统一取 min=22 会在顶部**漏出 9px 灰白内衬**，把角色整体往下顶。
   > 单图检测（`detect_border`，用于样本数 < 2 的孤立尺寸）判据是：
   > 从最外圈往内逐行/列取**中央 35% 区域的颜色标准差 σ**，找 **σ 骤升**处
   > （`σ(i) > max(30, 2.5·基线)`）—— 框体内部 σ 平缓（≤22，含冠军卡的橙金渐变），
   > 一进入角色画立刻跳到 50~130。
   > ⚠️ **`BORDER_CENTRAL` 取 0.70 是个大坑（第三、五次返工的根因）**：框体是**圆角矩形**，
   > 靠近四个角的地方角色画会**提前**侵入到边缘列/行，把 σ 拉高 ⇒ 扫描在圆角处提前触发、
   > 量出的内缩量偏小。实测 `electro-wizard` 左侧 σ 只到 29（差一点不触发 ⇒ 量对 34），
   > 右侧却到 35.7（跨过阈值 ⇒ 量成 16）—— 同一个对称的框被量成 **L=34 / R=16**。
   > 逐列剖面证明左侧内缘 x=34、右侧内缘 283−249=34，本来就对称。
   > 后果：`crop_border` 左裁 34px、右只裁 16px ⇒ 裁后画布中心比角色画中心**偏右 9px**
   > ⇒ 遮罩一裁，**角色整体左移 9px**（= 用户说的「卡牌不在中间、往右一点」）。
   > 收到中央 **35%** 后各尺寸组的 `|L−R|` 从 18 降到 0~1。
   > 核对办法（`diag_crop.py`）：算出「裁框后中心」在**原画布坐标系**里与画布中心的差，
   > 现在 12 个样本全部 ≤0.3px（旧几何是 +9px）。
   > ⚠️ **基线必须取「扫描过程中的运行最小值」，不能取「前一行」**：
   > 框体→角色画的过渡常常是**渐进爬升**的（`giant` 顶部 σ 走 14 → 30 → 51），
   > 用前一行当基线时每一跳都不到 2.5 倍 ⇒ 永远不触发、一路跑到 cap（实测漏检）。
   > ⚠️ 也不能只看「σ 小于某阈值」：`freeze.png` 的角色画是**平滑渐变**
   > （冰霜特效，σ 只有 20 上下），任何固定阈值都会要么停在框体中间、要么吃进画面。
   > σ 必须用**非预乘**的原始 rgb 算：预乘后会被辉光的 alpha 梯度放大，测不出来。
   > 自检：`_avg_groups.py` 把同尺寸组**平均**成一张图（角色画互相抵消、框体留下），
   > `_hueview.py` 把单张卡按**色相分类**打成 ASCII —— 不用看图就能读出框体内缘在第几行。
4. **颜色空间**：注入画布必须是**预乘 float32、rgb 0–255、alpha 0–1**，
   与渲染器量纲一致。rgb 用 0–1 会整块变黑，alpha 用 0–255 会变惨白。
5. **素材是调色板 PNG（P 模式）**：必须先 `convert("RGBA")` 再 resize，
   否则调色板索引被当像素插值，整张变黑。

图标名与内部 Key 常对不上（`IceGolemite`→`ice-golem`、`Assassin`→`bandit`、
`DarkMagic`→`void`、`MergeMaiden`→`spirit-empress`…），所以按
**内部 Key → 英文卡名 → 中文卡名** 依次归一化匹配，再前缀/后缀容错。
